Collaboration — shared database live

Live sync

Status: this board now reads and writes a shared database (Supabase), so a status or evidence change by any member appears on every other member’s screen. Your browser’s local storage is only an offline fallback — if the database cannot be reached, the board keeps working locally and the sync pill reads “Sync: Local only”.

How it works: Members select their name to attribute ordinary task and evidence updates. Each assigned AI model reviews filed evidence against the acceptance criteria and records the approval via its connected project tools, using AI Approved. The dashboard shows those decisions but does not allow the unauthenticated name selector to grant approval. Human approval is needed only at the production-readiness stage, for the six launch gates. Security note: the name selector is not real authentication; authenticated role-based access and tighter database policies must be implemented before production.

Data model (spec):

  • users — id, name, role, department, ai_agent, email, auth provider, active
  • tasks — id, title, owner_id, department, priority, day, due_date, acceptance_criteria, status, evidence, updated_by, updated_at
  • evidence — id, task_id, type (pr / link / screenshot / deliverable), url, uploaded_by, verified_by, verified_at
  • launch_gates — id, name, owner_id, status, evidence_url, approved_by, approved_at
  • audit_log — id, task_id, actor_id, old_status, new_status, timestamp

Auth (Day 1): pick your name before changing anything; the audit log records every change with your name. Step 2 adds named Supabase Auth logins for all 40 members; then only the task owner, their department lead, or Dharma can change a task. Evidence links must be public or shared with the team.

Product / Chatbot

Parkday Guide chatbot

Planned, not live yet

A chatbot built with the Parkday Guide site, to help visitors plan trips to all 64 national parks. This is the plan and spec panel only — there is no working AI backend yet.

Scope

  • Answer park questions: best time, fees, permits, trails, access, and nearby towns.
  • Help plan trips: suggest parks, routes, and itineraries from the trip planner.
  • Use parks.json data as the source of truth — answers come from the verified park data, not from memory.
  • No fabricated facts: if a fact is not in parks.json or an official source, the chatbot says it does not know instead of guessing.
  • Human-reviewed answers: chatbot replies are reviewed by the Content team (Akhil / Rakesh) before they ship.

Production plan

  • Verified-data retrieval only: the chatbot answers from parks.json and published signed guides only. It links every answer to the park page it used.
  • Never fabricates facts: if the data has no answer, it says it does not know and points to the park page or NPS.gov.
  • Prototype Day 4 (Nov 18): Raghava / Abhi build the interface on Tier 1 park data; Vijay question flows approved by Akhil.
  • Answer testing Day 6 (Nov 20): Rakesh / Teja test every answer for fabricated facts; fixes applied same day.
  • Production integration Day 7 (Nov 21): Vishnu integrates the chatbot on the live site, with the data feed from Sai / Chaitanya.
